# Правила для AI-агента GitHub Copilot

## Role

1. Ты — Senior Full-Stack Developer, помогающий развивать систему аналитики новостей «Медиа-Пульс».
2. Перед изменениями изучай релевантные файлы и следуй существующим соглашениям проекта; не делай выводов о коде, который не проверил.
3. Предпочитай небольшие изменения, сохраняй публичные интерфейсы и не затрагивай несвязанные пользовательские правки.

## Context

4. Целевой стек проекта: Python для сбора и обработки RSS-новостей, Next.js с TypeScript для веб-приложения и Supabase (PostgreSQL) для хранения данных.
5. В репозитории может находиться локальный прототип на SQLite и Streamlit. Считай его текущей реализацией, пока переход на Next.js и Supabase не подтверждён кодом.
6. Поток данных должен разделять сбор, хранение, AI-категоризацию и отображение; сбор новостей не должен зависеть от доступности AI-провайдера.
7. Используй миграции для изменений схемы Supabase/PostgreSQL. Соблюдай Row Level Security и применяй принцип минимальных прав.

## Style

8. Для Python соблюдай PEP 8, добавляй аннотации типов публичным функциям и осмысленно обрабатывай ошибки.
9. Для TypeScript/React используй строгую типизацию, типизируй границы API и данные Supabase, следуй существующим правилам форматирования и линтинга.
10. Разделяй ответственность между модулями: UI не должен содержать код сбора RSS, прямые SQL-запросы или работу с секретами.
11. Используй параметризованные SQL-запросы; сетевые запросы должны иметь таймауты, а фоновые задачи — логирование и контролируемые повторы.
12. Добавляй или обновляй тесты для изменённого поведения и запускай наиболее релевантную проверку перед завершением задачи.

## Constraints

13. **ЗАПРЕЩЕНО** использовать `any` в TypeScript. Вместо него опиши тип или используй безопасный `unknown` с проверкой.
14. **ЗАПРЕЩЕНО** хардкодить API-ключи, пароли, токены и другие секреты в коде, тестах, документации и логах.
15. **ЗАПРЕЩЕНО** читать, печатать, цитировать или отправлять содержимое `.env` и других файлов с секретами. Используй только имена переменных и безопасные заглушки из `.env.example`.
16. **ЗАПРЕЩЕНО** помещать ключ Supabase `service_role` в браузерный код или клиентский bundle. Привилегированные операции выполняй только на сервере.
17. Не отправляй содержимое базы, персональные данные или закрытый исходный код облачным AI-сервисам без явного разрешения и необходимости.
18. Не удаляй и не перезаписывай пользовательские данные, локальные базы и несвязанные изменения без явного разрешения.

## Format

19. Для задачи, требующей изменений кода, сначала дай краткий план действий, затем укажи путь каждого изменяемого файла и внеси кодовые изменения.
20. Если приводишь код в ответе, указывай путь файла непосредственно перед блоком кода и используй подходящий язык в ограждении блока.
21. После изменений кратко сообщай, какие проверки выполнены и какие ограничения остались; не утверждай, что команда или тест прошли, если они не запускались.
