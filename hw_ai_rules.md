# Правила AI-разработки: «Медиа-Пульс»

## 1. О проекте

«Медиа-Пульс» собирает новости из RSS-источников, сохраняет историю публикаций, присваивает им тематические категории и показывает аналитику в веб-приложении. Целевая архитектура разделяет сбор данных, хранение и пользовательский интерфейс; в текущем прототипе репозитория используются Python, SQLite и Streamlit, а целевой full-stack вариант предусматривает Next.js и Supabase.

## 2. Технологический стек

- **Сбор и обработка данных:** Python, `feedparser`, `requests`; плановые задачи запускаются отдельно от веб-приложения.
- **AI-категоризация:** OpenRouter через HTTP API; провайдер и модель задаются конфигурацией, а не встраиваются в бизнес-логику.
- **Текущий прототип:** SQLite для локальных данных и Streamlit для дашборда.
- **Целевое веб-приложение:** Next.js и TypeScript с включённым strict mode.
- **Целевая база данных:** Supabase (PostgreSQL); изменения схемы оформляются миграциями.
- **Проверки:** unit-тесты для нормализации, дедупликации, запросов и обработки ошибок; интеграционные тесты используют временную или тестовую базу.

## 3. Стиль кода и архитектура

### Python

- Соблюдать PEP 8; добавлять type hints к публичным функциям, важным параметрам и возвращаемым значениям.
- Использовать осмысленные имена; не применять `Any` и подавление ошибок типов без обоснованной необходимости.
- Не выполнять сетевые запросы и побочные действия при импорте модулей. Использовать таймауты, структурированное логирование и контекстные менеджеры для ресурсов.
- Не скрывать сбои: сохранять диагностическую ошибку и состояние обработки, чтобы повторный запуск мог продолжить работу.

### TypeScript и Next.js

- Использовать TypeScript в строгом режиме, ESLint и явные типы для границ API и данных Supabase; избегать `any`.
- Разделять серверный и клиентский код. Секреты и привилегированные запросы должны оставаться на сервере.
- Компоненты интерфейса не должны содержать логику сбора RSS, прямые SQL-запросы или секреты доступа.

### Архитектурные правила

- Разделять сбор RSS, хранение, AI-обработку и интерфейс на независимые модули с чёткими ответственностями.
- Делать импорт новостей идемпотентным: дедуплицировать по нормализованной ссылке и сохранять время обнаружения и результат каждого запуска.
- Выполнять AI-категоризацию асинхронно относительно сбора. Сначала сохранять статью, затем обрабатывать очередь со статусами, ограниченными повторами и диагностикой ошибок.
- Хранить схему БД и индексы в версионируемых миграциях. Для Supabase включать RLS и проверять политики доступа; ключ `service_role` никогда не использовать в браузере.
- `.env` не коммитить и не включать в контекст облачных LLM. Хранить только `.env.example` с безопасными заглушками; ключи деплоя задавать через секреты платформы.
- Не менять существующие публичные интерфейсы, схему или крупные архитектурные границы без необходимости и тестов. Перед изменениями изучать соседний код и сохранять несвязанные пользовательские правки.
